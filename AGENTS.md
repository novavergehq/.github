# novavergehq/.github — Agent Entry Point

**Repository role:** Organization GitHub profile and shared repository metadata. W0's approved Programme Runbook, NVA-SDLC-001 and Golden documentation authority remain controlling. The [NVA-GH-OPS-001 proposal](https://github.com/novavergehq/novaverge-engineering/pull/3) is not enforced until independently approved and adopted.

Mandatory for all agents before every task: identify exact repository/branch/HEAD, existing issues, protected checks and authorization; read the current W0 decision and controlling documents; avoid duplicate work; perform the smallest correct change and focused validation; create reviewed PRs rather than direct main commits. Do not treat the special .github repository as a universal Copilot instruction mechanism or release-policy authority. Keep the organization profile lightweight. Repository-level agent instructions and protected CI must be adopted separately where supported.

No bypass of checks, unapproved paid billing, speculative workflow runs, token exposure, evidence deletion, history rewrite, or deployment. Preserve any historical evidence with hash/readback before approved offloading. On completion report exact SHA, checks, changed files, GitHub resource impact, approvals and rollback. Agent text guides conduct; protection and review enforce outcomes.

## Permanent business-delivery closure contract (NVA-SDLC-001)

On every assigned delivery cycle, reconcile the current Founder business issue with the existing Golden/Programme Runbook, approved source contracts and the controlling NVA-SDLC delivery status in [novaverge-engineering PR #3](https://github.com/novavergehq/novaverge-engineering/pull/3). This links to proposed executable controllers; it is NOT a second architecture authority or a release approval.

Accept a business outcome, discover relevant existing work, implement only bounded authorized changes, run focused positive/negative tests, repair failures in the same task, verify the exact deployed/runtime consequence when applicable, and post an evidence-based receipt to the original controller. Do not claim closure from a source merge, stale PR approval, document entry, simulated HTTP fixture or self-reported test. Report specific HOLD for unconfigured credentials, missing human independent approval, inaccessible private backend or unauthorized data changes; never silently broaden privilege or open overlapping programmes.

When a cycle cannot proceed, identify the exact blocked phase, evidence and permitted next operation. Never ask W0 to redefine a known schema, API or code standard already supplied by the Golden authority. Existing local repository security/release controls always take precedence over a generic agent prompt. Preserve review and branch protections; do not automate production or database changes outside their existing authority.
